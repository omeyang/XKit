# 1.23 分支与 `main` 的功能差异说明

本文档**仅存在于 `develop-1.23-release` 分支**，用于记录该分支相对 `main`（Go 1.24.6）在语言/依赖降级后残留的运行时行为差异，方便下游在两分支间切换时定位问题。

> 绝大多数差异是机械降级（`testing.B.Loop` 这个 Go 1.24 API 的还原），没有功能影响。本文仅列举**会影响调用方可观察行为**的差异。

---

## 差异 1：`xdlock` 不再把 `concurrency.ErrLockReleased` 映射为 `ErrNotLocked`

**位置**：`pkg/distributed/xdlock/etcd.go` · `wrapEtcdError`

### 背景

`concurrency.ErrLockReleased` 是 `go.etcd.io/etcd/client/v3` **v3.6.0 才引入** 的 sentinel，本分支因 Go 1.23 最低版本限制把 etcd 客户端锁定在 **v3.5.21**，该符号不存在。

### 行为差异

| 场景 | `main`（etcd v3.6.8） | `develop-1.23-release`（etcd v3.5.21） |
|---|---|---|
| etcd session 提前过期后调用 `Unlock` | 返回 `xdlock.ErrNotLocked`（包装原始错误） | 返回原始 etcd 错误（未包装，不可用 `errors.Is(ErrNotLocked)` 判定） |

### 下游需要做什么

如果业务代码依赖 `errors.Is(err, xdlock.ErrNotLocked)` 区分"锁被 session 提前释放"的情况，在本分支上需要：

1. 接受返回的原始 etcd 错误，或
2. 同时判断一次底层错误链（但本分支的 etcd 不导出对应 sentinel，只能按错误消息字符串兜底，不推荐）。

**推荐做法**：在本分支上不要依赖这一映射，把"解锁时锁已释放"当作一般错误处理即可——该路径本来就是异常路径，不应出现在 happy path 的断言里。升级到 `main` 后可以恢复使用 `ErrNotLocked` 断言。

## 差异 2：`xpulsar.OAuth2` 凭证校验时机提前

**位置**：`pkg/mq/xpulsar/auth.go` · `OAuth2`

### 背景

`pulsar-client-go` 在 v0.16 与 v0.18 之间调整了 OAuth2 凭证的加载时机：

- **v0.18+**（`main` 使用）：凭证文件读取与 issuer 访问**延迟到首次使用**（例如第一次创建 Producer/Consumer 时）。
- **v0.16**（本分支使用）：**构造时**即尝试加载凭证文件并访问 issuer。

### 行为差异

| 场景 | `main`（pulsar v0.18） | `develop-1.23-release`（pulsar v0.16） |
|---|---|---|
| `credentialsPath` 文件不存在 | `OAuth2()` 返回成功，Producer/Consumer 创建时报错 | `OAuth2()` 可能直接报错，或返回的 `AuthMethod` 内部 `auth` 字段为 nil |
| `issuerURL` 不可达 | `OAuth2()` 返回成功，首次网络调用时报错 | `OAuth2()` 构造阶段即尝试访问 |

`xpulsar` 本身只做了入参的非空/去空白校验，并不拦截底层 SDK 的时机差异。

### 下游需要做什么

1. **不要断言 `AuthMethod.Authentication() != nil`**：本分支上 SDK 构造失败时该字段可能为 nil，而 `OAuth2()` 仍可能返回无错。
2. **凭证错误处理路径应同时考虑"构造时报错"与"首次使用时报错"**：两个分支上错误暴露点不同，写一次兼容两边。
3. 若需要在启动阶段提前暴露凭证问题，本分支**天然具备**这个效果；`main` 上则需要主动建立一次 Producer/Consumer 去触发。

## 其他（不影响功能）

以下属机械降级，列在这里只是便于代码审查时对照，不影响调用方：

- `for b.Loop()` → `for i := 0; i < b.N; i++`（Go 1.24 基准测试 API）。
  `sync.WaitGroup.Go` 已不再是差异项——`main` 锁定 Go 1.24.6 后同样不使用该 1.25 API，两分支写法一致。
- 由源码构建的工具版本上限更低：`golangci-lint v2.3.1`（v2.4.0+ 要求 go1.24.0）、
  `actionlint v1.7.7`（v1.7.10+ 要求 go1.24.0）；`govulncheck v1.1.4` 与 `gocyclo v0.6.0` 与 `main` 相同。
- 依赖版本整体下调：etcd 3.6→3.5、k8s 0.34→0.32、OTel 1.41→1.38、pulsar 0.18→0.16、mongo driver 2.5→2.4、ClickHouse 2.43→2.32 等。

## 维护约定

- 以后如发现新的**可观察行为差异**，追加到本文件并在对应源文件函数注释中加一句 `// 1.23 分支行为差异: 见 docs/08-1.23-branch-notes.md`。
- 本文件不随 `main` 合并——合并 `main` 时冲突解决策略是**保留本文件**。
